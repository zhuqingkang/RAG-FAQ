# EduRAG 集成问答系统 · 开发文档（简略版）

> 单服务、双链路的教育领域问答系统：FAQ（MySQL + BM25 + Redis）优先，未命中转 RAG（Milvus + BGE 精排 + 大模型生成）。
> 完整版见 [开发文档-详细版.md](开发文档-详细版.md)。

![项目结构图](architecture.svg)

---

## 1. 快速启动

```bash
# 前置：MySQL、Redis、Milvus 已启动；rag_qa/models 下模型齐全
pip install -r requirements.txt

cd integrated_qa_system
python app.py            # Flask   → http://127.0.0.1:5000
python app_async.py      # FastAPI → http://127.0.0.1:8000
```

启动顺序：FAQ 预热（jieba + BM25 索引，秒级）→ RAG 预热（后台加载 BGE-M3 / reranker，数十秒）→ 开始接收请求。

## 2. 架构一眼看懂

```
浏览器 → 唯一前端（templates/ + static/）
        → app.py / app_async.py        入口层
        → qa_router.py                 路由层（唯一判定入口）
             ├─ FAQ  mysql_qa/  → BM25 → Redis 缓存 → MySQL knowledge
             │       返回 (answer, need_rag)，need_rag 决定是否降级
             └─ RAG  rag_qa/    → 混合检索 → 父块去重 → rerank → 注入历史 → LLM 生成
        → chat_store（SQLite）落库 → 返回 JSON
```

| 链路 | 数据源 | 检索 | 生成 | 耗时 | 触发条件 |
|---|---|---|---|---|---|
| FAQ | MySQL `knowledge` | BM25 + softmax，最高分 > 0.85 | 直接取标准答案 | 毫秒 | `auto` 下永远先试 |
| RAG | Milvus `edurag_final` | BGE-M3 dense(0.7)+sparse(0.3) → 父块去重 → reranker Top2 | DashScope 生成（带最近 5 轮历史） | 秒 | `need_rag=true` 或 `mode=rag` |

`mode` 三态：`auto`（默认，FAQ 优先）/ `faq`（只查 FAQ）/ `rag`（只走 RAG）。

`auto` 由 FAQ 返回的 `need_rag` 驱动：命中即返回；未命中、答案为空或 FAQ 异常置 `true` 转 RAG；仅无效查询（`false` 且无答案）直接返回未命中，不为空查询白跑 RAG。

## 4. 接口速查

`POST /query`

```json
// 请求
{"query": "AI 学科的课程大纲", "session_id": 3, "mode": "auto", "source": "ai"}

// 响应
{"code": 0, "session_id": 3, "title": "AI 学科的课程大纲", "answer": "……",
 "found": true, "engine": "rag", "elapsed": 3.2145, "note": "FAQ 无可靠答案，已转 RAG"}
```

| 字段 | 说明 |
|---|---|
| `mode` | `auto` / `faq` / `rag`，非法值回退 `auto` |
| `source` | 学科过滤，仅 RAG 生效，取值见 `valid_sources` |
| `engine` | `faq` / `rag` / `none`，真正产出答案的链路 |
| `found` | `false` 时 `answer` 为兜底文案 |
| `note` | 过程说明，前端做悬浮提示 |

其余接口：`GET /`、`GET /api/meta`、`GET|POST /api/conversations`、`GET|PATCH|DELETE /api/conversations/{id}`、`GET /health`。

## 5. 关键实现要点

**包与导入**
- 每层都有 `__init__.py`，统一「包内相对、跨包绝对」；只有入口层改 `sys.path`，且只插项目根。
- 子包 re-export 常用类；包入口不做聚合导出，避免 `import torch` / jieba / modelscope 被连带加载。

**FAQ 链路**
- 单例 + 预热：`mysql_qa/utils/qa_service.get_qa_system()` / `ensure_ready()`。
- 索引：启动时 `select question from knowledge` → jieba 分词 → BM25；daemon 线程每 30 分钟重新同步。
- 判定：Redis `answer:{query}` 命中即返回；否则 BM25 打分 → softmax → 最高分 > 0.85 才算命中。
- 返回契约：`(answer, need_rag)`。命中问题但答案为空时不写缓存，按「无可用答案」置 `need_rag=true`。
- 命中后用最相似的历史问题去 MySQL 取标准答案，并回写缓存。

**RAG 链路**
- 单例 + 失败冷却 60 s：Milvus 或模型不可用时快速失败，避免每请求重连。
- 意图分流：BERT 分类器（`models/bert_query_classifier` 微调权重）先判断问题类型，「通用知识」不检索直接由 LLM 作答，「专业咨询」才进检索流程。
- 策略分派：LLM 选策略 → `strategy.strip()` → `retrieve_and_merge` 按策略分派到回溯 / 子查询 / HyDE / 直接检索（无法匹配时退化为直接检索）。
- 混合检索：dense 0.7 + sparse 0.3（`IP`，`k=retrieval_k`）→ 子块按 `parent_content` 去重还原父块 → `bge-reranker` 精排取 `candidate_m` 条。
- 对话历史：最近 5 轮问答格式化为 `Q:…/A:…` 注入提示词；单条 200 字、整体 1500 字，超出先丢更早的轮次。
- 生成：`rag_prompt(context, history, question, phone)` → DashScope；无可靠上下文时输出含客服电话的兜底句。

**会话存储**
- SQLite + WAL，库文件 `mysql_qa/data/chat_history.db`；线程本地连接 + 全局写锁。
- `add_exchange` 单事务写"一问一答"，顺带把默认标题自动改成首个问题（截断 24 字）。
- `recent_history(cid, turns=5)` 取最近 N 轮问答供 RAG 使用，只在转入 RAG 时查一次。
- `messages.meta` 形如 `FAQ · 耗时 0.0123 s`，前端据此还原引擎徽标。

**异步版差异**
- 阻塞调用全部 `run_sync` 进线程池；三套 `CapacityLimiter`：FAQ=`max(4, CPU)`、RAG=2、DB=32。
- 超时：FAQ 30 s、RAG 180 s（可用环境变量覆盖）。
- single-flight：key = `(question, mode, source, conversation_id)`，同刻相同 key 只算一次；会话进 key 是因为 RAG 会注入该会话的历史。

**LangChain 使用范围（langchain 1.4.4 / core 1.6.9）**
- 用：`PromptTemplate`（提示词模板）、`Document` / `BaseLoader`（文档载体与加载器基类）、`RecursiveCharacterTextSplitter`（中文切分）、`TextLoader`（.txt）。
- 不用：LCEL / Runnable / Chain / Agent / Retriever / Memory；检索直连 pymilvus，生成直连 DashScope。

## 7. 新增学科三步

1. 建目录 `rag_qa/data/{source}_data/`，丢进原始文档（pdf/docx/pptx/txt/图片）。
2. `config.ini` 的 `valid_sources` 追加 `"{source}"`。
3. 建库：`python -c "from rag_qa.rag_main import main; main(query_mode=False, directory_path='rag_qa/data/test_data')"`，然后重启服务。

## 8. 缓存现状（四级缓存对照）

| 层级 | 是否实现 | 位置 | 命中后跳过 |
|---|---|---|---|
| 响应缓存 | **部分实现（仅 FAQ）** | Redis `answer:{query}`，读写均在 `BM25Search.search` | jieba 分词 + BM25 + MySQL |
| 语义缓存 | 未实现 | — | — |
| 检索缓存 | 未实现 | — | — |
| 嵌入缓存 | 未实现 | — | — |

- FAQ 的响应缓存是**精确字符串匹配**（无 TTL、无失效），"AI学科学费多少" 与 "AI 学科学费是多少" 不算同一条。
- RAG 链路四步全跑：BGE-M3 编码 → Milvus 混合检索 → rerank → LLM 生成，**没有任何一层缓存**。
- `rag_qa/data/.cache/` 的 `catalog/documents/chunks` 是**离线建库缓存**（省 OCR 与切块），不属于在线四级缓存。
- single-flight 只合并同一时刻的并发请求，不能跨时间复用。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 首个 RAG 请求特别慢 | BGE 模型懒加载 | 预热已在后台执行；未完成时耐心等待 |
| FAQ 全部不命中 | 语料变大后 softmax 最高分被稀释 | 已知限制（阈值与语料规模耦合） |
| RAG 一直返回未命中且 note 有 Milvus 报错 | 向量库不可用 | 检查 Milvus、库名 `test5` 与集合名 |
| 改了文件但建库结果没变 | 目录 mtime 未变（原地覆盖） | `[cache] verify_files = True` |
| MySQL 重启后 FAQ 持续报错 | 单连接无重连 | 重启服务 |
| 前端学科选了 `ops` 检索为空 | 无对应 `ops_data` 语料 | 补语料 |

## 10. 已落地的优化（摘要）

| 优化项 | 类型 | 做法 |
|---|---|---|
| 重库延迟加载 | 启动 | `torch` / `pymilvus` / BGE 相关库改为函数内 import |
| 启动预热 | 启动 | FAQ 同步预热；RAG 后台加载并主动触发 BGE / reranker 权重 |
| 单例 + 失败冷却 | 稳定性 | 双重检查锁；初始化失败 60 s 内快速失败 |
| 离线三级缓存 | 建库 | `catalog` / `documents` / `chunks` + 三重校验 + 原子写 + 版本号 |
| FAQ 响应缓存 | 延迟 | Redis `answer:{query}`，命中直接返回（精确匹配、无 TTL） |
| 索引常驻 + 定时同步 | 延迟 | BM25 常驻内存；每 30 分钟同步 MySQL |
| 并发去重 | 并发 | single-flight，同刻相同 key 只算一次 |
| 线程池 + 三套闸门 | 并发 | FAQ / RAG / DB 分别限流 + 分层超时 |
| 父子块 + 混合检索 + 精排 | 检索 | 子块 300 检索、父块 1200 喂 LLM；dense 0.7 + sparse 0.3；rerank Top2 |
| 意图分类修正 | 检索 | 分类器指向 `models/bert_query_classifier`，加载微调权重 |
| 四策略分派 | 检索 | 回溯 / 子查询 / HyDE / 直接检索按 LLM 策略真正分派 |
| 通用知识直答 | 检索 | 通用知识不检索，直接 LLM 作答 |
| 幻觉四道闸 | 答案质量 | FAQ 阈值直答 → 上下文收窄 → prompt 兜底句 → 出口空答案兜底 |
| 问答判定收口 | 工程化 | Flask / FastAPI 共用 `qa_router` 一份判定 |
| `need_rag` 调度契约 | 工程化 | FAQ 逐层返回 `(answer, need_rag)`，无效查询不触发 RAG |
| 多轮对话 | 体验 | 最近 5 轮问答按预算截断后注入提示词 |

> 完整机制、代码位置与效果对照见详细版 §19。

## 11. 后续可添加 / 可修改（摘要）

| 位置 | 现状 | 可添加 / 可修改 |
|---|---|---|
| FAQ 阈值 | 固定 0.85，与语料规模耦合 | 换打分方式、阈值移入配置 |
| MySQL 连接 | 单连接无重连 | 加重连或连接池 |
| LLM 客户端 | 两处封装、参数不一致 | 抽公共 `llm_client` |
| 调试输出 | 已清理：两个临时 `test.py` 与各模块 `__main__` 自测块已删除 | 需要时另建独立脚本，不要塞回业务模块 |
| 学科配置 | `valid_sources` 含 `ops` 但无语料 | 补语料或移除 |
| 密钥管理 | `config.ini` 明文 | 环境变量注入 |
| 观测字段 | 仅 `engine` / `elapsed` / `note` | 补 `cached` 与分段耗时 |
| 子查询清洗 | 直接 `split('\n')`，未过滤空行与编号 | 清洗后判空再检索 |

> 逐条说明见详细版 §15。
